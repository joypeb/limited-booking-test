# 데이터 모델: 0단계 계약 검토용

[명세](spec.md)와 계획서 2·4·5절에서 추출한 설계다. 실제 스키마·마이그레이션·저장 테스트는 아직 없다.

## 예약 대상

| 필드 | 의미·타입 | 제약 |
| --- | --- | --- |
| id | UUID 식별자 | 불변, 조회 응답 필수 |
| name | 문자열 이름 | 앞뒤 공백 제거 후 코드 포인트 1~100개, `😀` 1개는 1자 |
| capacity | 최초 수량, 정수 | 0~1,000, 생성 후 변경하지 않음 |
| available | 남은 수량, 정수 | 최초 capacity, 0~capacity |
| createdAt | 생성 UTC 시각 | 저장 설계 필드, ResourceView 응답에는 포함하지 않음 |

대상은 여러 예약에 연결된다. 이름의 공백 제거 후 길이는 실제 업무 검증으로 확인해야 한다. 입력의 원문 길이와 정규화 후 길이를 혼동하지 않는다.

## 예약과 성공한 생성 키

| 필드 | 의미·타입 | 제약 |
| --- | --- | --- |
| id | 예약 UUID | 불변 |
| resourceId | 대상 UUID | 필수, 존재하는 대상 참조, 불변 |
| userId | 인증 사용자 UUID | 클라이언트 입력·응답 필드 아님, 불변 |
| idempotencyKey | 생성 키 문자열 | 사용자와 함께 유일, 1~64 ASCII 영문·숫자·밑줄·하이픈, 변환하지 않음 |
| status | 상태 | CONFIRMED 또는 CANCELLED |
| createdAt | 생성 UTC 시각 | 저장된 마이크로초 정밀도 값, 불변 |
| cancelledAt | 취소 UTC 시각 또는 null | CONFIRMED에서 null, CANCELLED에서 필수 시각 |

성공한 예약이 키 기록이다. 별도 키 엔티티·TTL 삭제는 추가하지 않는다. 사용자·키당 예약은 최대 1개다. 같은 사용자의 다른 키, 다른 사용자의 같은 키는 별개의 요청이다. 대상이 바뀌어도 사용자·키의 범위는 공유된다.

| 현재 상태 | 행동 | 결과 | 남은 수량 변화 |
| --- | --- | --- | --- |
| 성공 기록 없음 | 수량 있는 대상 예약 | CONFIRMED·성공 키 기록 | -1 |
| 성공 기록 없음 | 품절·입력 오류·의존성 장애 | 성공 기록 없음 유지 | 0 |
| CONFIRMED | 소유자 취소 | CANCELLED·취소 시각 | +1 |
| CANCELLED | 소유자 중복 취소 | 동일 CANCELLED·취소 시각 | 0 |
| CONFIRMED 또는 CANCELLED | 같은 키·같은 대상 생성 재요청 | 최초 CONFIRMED 응답 재현, 현재 상태 유지 | 0 |
| CONFIRMED 또는 CANCELLED | 같은 키·다른 대상 생성 | 키 충돌, 기존 상태 유지 | 0 |

취소 뒤 재요청의 생성 응답과 GET의 현재 상태는 서로 다른 조회 관점이다. 타인 접근은 404이며 업무 상태가 바뀌지 않는다.

## 불변식

- 대상별 `0 ≤ available ≤ capacity`, `available + CONFIRMED 예약 수 = capacity`.
- 예약당 수량은 1, 성공 키당 예약 최대 1개, 예약당 취소 복구 최대 1개.
- 실패 트랜잭션은 수량·예약을 부분 반영하지 않는다. 커밋 뒤 응답 유실은 실패 트랜잭션과 구분한다.
- 예약 행·성공 키는 취소 뒤에도 보존한다. 상태 재활성화·행 삭제는 없다.

## 문서 검토 데이터

**계약 사례**: 사례 ID, 관련 요구사항, 인증 사용자, 초기 대상·수량·예약·키, 요청, 상태 코드·오류 코드·헤더·응답 필드, 최종 남은 수량·활성 예약·키 기록을 가진다. 독립 사례는 초기 상태로 되돌려 판단하며 순차 사례는 앞 행의 최종 상태를 다음 행에 전달한다.

**결정 기록**: 선택, 이유, 대안, 영향, 설계·실행 상태를 가진다. JDBC·성공 예약에 키 보관·Redis 진입 제한의 세 결정을 각각 3~5줄로 작성한다.

**검토 증거**: 명령·종료 코드·검토 항목 수·실행 환경·미검증 범위·본인 설명 여부를 가진다. 미래 위치는 프로젝트 루트 `docs/test-evidence.md`다. 이 문서에서 실행 결과를 가정하지 않는다.
